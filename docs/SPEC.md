## 2. 목표와 해결할 문제

캘공은 Google 캘린더 전체를 상대방 계정에 등록하거나 복잡한 Google 공유 권한을 설정하지 않고도, 관리자가 사람별 링크마다 캘린더·일정 날짜 범위·접근 가능 시간을 제한해 일정을 보여주는 개인용 서비스다.

목표는 다음과 같다.

- 방문자는 자신에게 발급된 링크가 허용하는 일정만 편하게 확인한다.
- 관리자는 링크와 공개 범위를 언제든 생성, 수정, 폐기한다.
- Google 캘린더 변경을 거의 실시간으로 반영해 수동 동기화 부담을 최소화한다.

## 3. 주요 사용자

- 관리자: 서비스 소유자 1명. Google 캘린더를 연결하고 공유 정책을 관리한다.
- 방문자: 가족·지인. 별도 가입 없이 전달받은 링크로 허용된 일정을 열람한다.

## 4. 핵심 사용 흐름

### 4.1 관리자 공유 생성

1. 관리자가 직접 관리자 주소로 이동해 비밀번호로 로그인한다.
2. 새 공유에 이름을 붙이고 공개 캘린더, 전체 데이터 또는 일정 날짜 범위, 접근 가능 시작·종료 시각을 설정한다.
3. 저장 전에 방문자와 동일한 정책 결과를 미리 본다.
4. 공유 링크를 생성해 방문자에게 전달한다.

### 4.2 방문자 열람

1. 방문자가 공유 토큰이 포함된 링크를 연다.
2. 서버가 토큰, 폐기 여부, 접근 가능 시간을 검증한다.
3. 유효하면 허용된 캘린더와 전체 보존 데이터 또는 선택한 날짜 범위의 일정만 달력/목록 화면으로 보여준다.
4. 만료·폐기·오류 상태이면 일정 데이터 없이 이해 가능한 안내를 보여준다.

### 4.3 일정 동기화

1. 관리자가 Google 캘린더 연결을 승인한다.
2. 서비스가 초기 전체 동기화를 수행하고 이후 변경 알림을 구독한다.
3. 알림을 받으면 증분 동기화를 수행하고 열린 방문자 화면도 갱신한다.
4. 알림 누락, 채널 만료, 동기화 토큰 무효화는 복구 동기화로 보완한다.

## 5. 기능 요구사항

- **FR-001 Google 연결:** 관리자는 자신의 Google 계정을 OAuth로 연결·재연결·해제하고 연결 및 마지막 동기화 상태를 확인할 수 있어야 한다. 수동 동기화는 작업 대기·진행·재시도·성공·실패의 실제 결과를 관리자에게 알려야 한다.
- **FR-002 캘린더 동기화:** 서비스는 접근 가능한 하위 캘린더와 오늘 기준 과거 3개월부터 미래 3개월까지의 일정을 최초 전체 동기화하고 이후 변경·삭제를 증분 반영해야 한다.
- **FR-003 관리자 인증:** 관리자 대시보드의 모든 화면과 변경 API는 비밀번호 인증을 통과한 관리자만 사용할 수 있어야 한다.
- **FR-004 공유 CRUD:** 관리자는 커스텀 이름을 가진 공유 링크를 생성, 조회, 수정, 즉시 폐기할 수 있어야 한다. 활성 공유 주소는 관리자 목록에서 다시 확인하고 복사할 수 있어야 한다.
- **FR-005 캘린더 범위:** 공유 생성 화면은 `전체 캘린더`를 기본값으로 제공하고 개별 캘린더를 제외할 수 있어야 한다. `전체 캘린더` 공유에는 나중에 발견된 새 캘린더도 자동 포함하고, 하나라도 제외한 `선택 캘린더` 공유에는 저장 당시 허용 목록만 사용해 새 캘린더를 자동 포함하지 않아야 한다.
- **FR-006 일정 날짜 범위:** 각 공유는 현재 로컬 read model 전체를 제공하는 `ALL` 또는 양끝을 포함하는 시작일·종료일만 제공하는 `SELECTED` 날짜 모드를 가져야 한다. `SELECTED`의 범위 밖 일정은 서버 응답에 포함하지 않아야 한다.
- **FR-007 접근 가능 시간:** 각 공유는 접근 시작·종료 시각을 가질 수 있어야 하며 서버 현재 시각이 범위 밖이면 접근을 거부해야 한다.
- **FR-008 링크 방문:** 방문자는 계정 생성이나 추가 입력 없이 전달받은 링크를 열어 유효한 공유를 확인할 수 있어야 한다.
- **FR-009 공개 화면:** 방문자 화면은 모바일 인앱 브라우저와 데스크톱에서 `목록`, `주간`, `월간` 보기를 직접 전환해 일정을 탐색할 수 있어야 하며 관리자 대시보드 링크나 이동 버튼을 포함하지 않아야 한다.
- **FR-010 미리보기:** 관리자 미리보기는 실제 방문자 응답과 동일한 정책 평가 로직과 일정 표현 컴포넌트를 사용해야 한다.
- **FR-011 변경 반영:** Google 변경 알림 수신 후 동기화가 완료되면 열린 방문자 화면은 새로고침 없이 최신 데이터를 다시 조회해야 한다.
- **FR-012 실패 복구:** 만료된 알림 채널은 갱신하고, 유효하지 않은 증분 토큰은 안전한 전체 재동기화로 복구해야 한다.
- **FR-013 일정 상세:** 일반 일정은 제목, 날짜와 시작·종료 시간, 장소, 설명만 방문자에게 제공해야 한다. 참석자, 주최자 연락처, 첨부파일, 화상회의 정보와 Google 이벤트 원문은 제공하지 않아야 한다.
- **FR-014 비공개 일정:** Google에서 `private`로 표시된 일정은 날짜와 시간만 `비공개 일정`으로 보여주고 제목, 장소, 설명은 제공하지 않는 것을 개인정보 보호 기본값으로 한다.

## 6. 비기능 요구사항

### 성능

- 제안 목표: 목표 Raspberry Pi 환경과 대표 데이터셋에서 방문자 일정 API의 p95 응답 시간이 500ms 이하, 초기 화면의 주요 콘텐츠 표시가 p95 2초 이하이어야 한다.
- 제안 목표: 유효한 Google 변경 알림을 서버가 받은 시점부터 로컬 일정 반영까지 p95 10초 이하이어야 한다.
- 열린 화면은 서버 변경 신호를 받거나 연결 복구 시 데이터를 다시 조회한다.

### 보안·개인정보

- 공유 토큰은 별도 256비트 `SHARE_LINK_SECRET`, 공유 ID와 링크 버전으로 HMAC-SHA-256 파생하고 데이터베이스에는 단방향 해시와 버전만 저장한다.
- 새 링크는 URL fragment에 원문 공유 토큰을 넣어 최초 HTTP 요청에서 제외한다. 클라이언트는 fragment를 즉시 지우고 same-origin POST로 제한된 방문자 세션을 만든 뒤 깨끗한 URL로 전환한다. 원문 토큰과 OAuth 토큰은 로그에 남기지 않는다.
- 방문자 일정 API는 모든 요청에서 공유의 허용 캘린더, 일정 날짜 범위, 접근 시간, 폐기 상태를 서버에서 다시 검증한다.
- 관리자 세션 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`를 사용하고 상태 변경 요청에 CSRF 방어를 적용한다.
- 관리자 비밀번호는 검증된 메모리/CPU 비용 해시로 저장하고 로그인 시도에 속도 제한을 둔다.
- Google refresh token은 환경 비밀값으로 암호화한 뒤 저장하며 최소 읽기 범위만 요청한다.
- 공개 응답은 공유 캐시를 금지하고 `noindex` 및 엄격한 Referrer Policy를 적용한다.
- 만료, 폐기, 존재하지 않는 링크의 응답은 일정 내용이나 내부 식별자를 노출하지 않는다.

### 접근성

- 제안 기준은 WCAG 2.2 AA다. 키보드만으로 로그인, 공유 편집, 날짜 탐색이 가능해야 한다.
- 색상만으로 캘린더나 상태를 구분하지 않고 포커스 표시, 충분한 대비, 의미 있는 레이블을 제공한다.

### 호환성

- 최신 KakaoTalk 인앱 브라우저를 포함한 모바일 WebView, Safari, Chrome의 최근 두 주요 버전을 우선 지원한다.
- JavaScript가 비활성화된 환경은 MVP 지원 범위에서 제외한다.

### 운영

- 서비스는 단일 Raspberry Pi 인스턴스와 영속 로컬 디스크를 전제로 한다.
- 구조화 로그, 상태 확인 엔드포인트, 마지막 동기화 시각과 오류 상태를 제공한다.
- SQLite 백업과 복원 절차를 문서화하고 배포 전 복구 가능 백업을 검증한다.

## 7. 데이터 요구사항

- 캘린더: Google 캘린더 ID, 표시 이름, 색상, 시간대, 삭제/활성 상태, 마지막 동기화 상태.
- 일정: Google 이벤트 ID와 캘린더 ID, 상태, 시작/종료, 종일 여부, 원래 시간대, 반복 일정 연결 정보, visibility, 제목, 장소, 설명, 변경 버전. 설명은 HTML로 신뢰하지 않고 일반 텍스트로 정규화한다.
- 공유: 내부 ID, 커스텀 이름, `ALL` 또는 `SELECTED` 캘린더 범위 모드, 토큰 해시·링크 버전, `ALL` 또는 `SELECTED` 일정 날짜 모드와 선택 날짜, 접근 시작/종료시각, 폐기 상태와 감사 시각.
- 공유-캘린더 허용 목록: `SELECTED` 공유에만 저장한다. `ALL` 공유는 조회 시 현재 활성 캘린더 전체를 사용한다.
- 인증: 관리자 비밀번호 해시의 외부 비밀값 계약, 만료·폐기 가능한 관리자 세션.
- Google 연결: 암호화된 refresh token, scope, 연결 상태. access token은 영속 저장하지 않는다.
- 동기화: 캘린더별 sync token, 알림 채널 ID·resource ID·만료시각, 재시도 가능한 작업 상태.
- 시간 값은 저장 시 UTC를 기준으로 하고, 종일 일정의 날짜와 원본 시간대를 별도로 보존한다.

일정 read model은 `Asia/Seoul`의 오늘을 기준으로 3개월 전부터 3개월 후까지의 이동 구간만 보존한다. 구간 밖 데이터는 새 구간 동기화가 성공한 뒤 제거하며, 삭제된 이벤트 tombstone은 삭제 반영 트랜잭션 이후 별도로 장기 보존하지 않는다. Google 이벤트 원문 전체는 저장하지 않는다.

## 8. 외부 연동

- Google OAuth 2.0 Web Server 흐름: 관리자의 읽기 권한 승인과 refresh token 발급.
- OAuth scope는 캘린더 목록용 `calendar.calendarlist.readonly`와 이벤트용 `calendar.events.readonly`로 제한한다.
- Google Calendar API: CalendarList 및 Events 읽기, 증분 동기화, CalendarList/Events watch 채널.
- 공개 HTTPS 엔드포인트: Google 변경 알림 수신. 알림은 변경 힌트로만 취급하고 실제 내용은 API로 다시 조회한다.
- 배포: 사용자가 별도로 지시할 때 `deploy-project` 스킬을 통해 Raspberry Pi용 이미지와 대시보드 handoff를 준비·검증한다.

## 9. 범위 제외

- 방문자의 일정 생성·수정·삭제 또는 참석 응답
- 여러 관리자, 여러 Google 계정, 다중 테넌트
- 방문자 회원가입, 소셜 로그인, 사람별 계정 관리
- 네이티브 모바일 앱과 푸시 알림
- Google 캘린더로의 쓰기 동기화
- 링크 전달 방지, 방문자 신원 보증, DRM 수준의 재공유 방지
- 반복 일정 편집기, 일정 초대 발송, 예약 가능 시간 추천
- 공개 배포 자체(별도 사용자 지시가 필요한 후속 단계)

## 10. 완료 조건

- AC-001 관리자가 Google 계정을 연결하면 선택 가능한 캘린더 목록과 초기 일정이 표시된다.
- AC-002 관리자가 이름·캘린더·전체 데이터 또는 일정 날짜 범위·접근 시간을 설정해 링크를 만들고 수정할 수 있으며 활성 주소를 목록에서 다시 복사할 수 있다.
- AC-003 허용 캘린더/기간 조합의 경계값 테스트에서 범위 밖 일정이 API와 HTML 어디에도 포함되지 않는다.
- AC-004 접근 시작 전, 종료 후, 폐기 직후의 링크가 일정 없이 일관된 접근 거부 화면을 반환한다.
- AC-005 미리보기와 동일 공유의 방문자 화면이 같은 기준 시각에서 동일한 일정 집합을 보여준다.
- AC-006 방문자 화면의 DOM과 탐색 요소에 관리자 경로 링크가 존재하지 않는다.
- AC-007 Google 이벤트 생성·수정·삭제 알림 후 증분 동기화와 열린 화면 갱신이 제안 지연 목표를 충족한다.
- AC-008 알림 누락, 채널 만료, API 429/5xx, sync token 410을 재현한 통합 테스트에서 데이터가 복구되고 중복 일정이 생기지 않는다.
- AC-009 공유 원문 토큰, 비밀번호, OAuth 비밀값과 `SHARE_LINK_SECRET`이 저장 DB 덤프(허용된 암호문 제외), 로그, 클라이언트 번들에 평문으로 나타나지 않는다.
- AC-010 단위·통합·브라우저 테스트와 lint, typecheck, build가 통과하고 Raspberry Pi 대상 이미지의 상태 확인이 성공한다.
- AC-011 키보드 핵심 흐름과 자동 접근성 검사에서 합의된 차단 위반이 없다.
- AC-012 백업에서 별도 검증 환경으로 SQLite 데이터를 복원하고 동일 공유 정책을 조회할 수 있다.
- AC-013 새 캘린더를 추가했을 때 `ALL` 공유에는 자동 표시되고, 하나 이상의 캘린더를 제외한 `SELECTED` 공유에는 관리자가 추가하기 전까지 표시되지 않는다.
- AC-014 일반 일정 응답에는 승인된 네 필드군만 있고 `private` 일정 응답에는 날짜·시간과 대체 제목만 있으며 제외 필드가 DB read model과 공개 응답에 나타나지 않는다.
- AC-015 날짜가 바뀌어 3개월 이동 구간이 전진한 뒤 새로 들어온 일정은 조회되고 구간 밖 일정은 성공한 재동기화 이후 제거된다.
- AC-016 새 fragment 공유 링크는 원문 토큰을 HTTP URL에 보내지 않고 `/share/:id`로 정리된 뒤 방문자 달력을 표시한다. 기존 `/s/:token` 링크도 계속 동작한다.
- AC-017 관리자가 수동 동기화를 시작하면 durable 작업 ID를 추적해 성공 시 완료 시각, 실패 시 안전한 오류 안내를 표시한다.
- AC-018 모바일과 데스크톱에서 목록·주간·월간 전환, 이전·오늘·다음 기간 탐색, 선택 기억이 동작한다. 주간은 월–일 가로축과 00:00–24:00 세로축에 일정을 시간대로 배치하고, 월간은 일정 이름을 표시하며 날짜 선택 시 해당 주간으로 전환한다. 여러 날 일정은 해당 날짜에 빠짐없이 표시된다.

## 11. 명시된 요구사항

다음은 `PROJECT_BRIEF.md`가 직접 확정한 내용이다.

- 프로젝트명은 캘공이며 개인 Google 캘린더를 지인에게 제한적으로 공유한다.
- 관리자 대시보드, 방문자 캘린더 화면, Google Calendar 자동 연동이 MVP에 포함된다.
- 공유마다 커스텀 이름, 공개 캘린더, 공개할 일정 기간, 방문 가능한 시간을 관리한다.
- 캘린더 선택 기본값은 모두 표시이며 개별 제외가 가능해야 한다.
- 방문자는 링크 주소의 세션 키로 추가 로그인 없이 접근한다.
- 관리자 대시보드는 비밀번호로 인증하고, 방문자 화면에는 대시보드 이동 버튼을 두지 않는다.
- 데이터 저장소는 SQLite, 외부 API는 Google Calendar API다.
- Raspberry Pi에 `deploy-project` 스킬로 공개 배포한다.
- 밝은 파랑 계열, 당근 Seed Design 또는 Toss를 참고한 간결한 디자인을 선호하고 무분별한 그라디언트 스타일을 피한다.
- 2026-08-25 사용자 결정에 따라 `전체 캘린더` 공유만 미래의 새 캘린더를 자동 포함하고, 하나라도 제외한 공유는 기존 허용 목록을 유지한다.
- 방문자에게 공개하는 일정 상세는 제목, 날짜·시간, 장소, 설명으로 제한한다.
- 로컬 일정 보존 범위는 `Asia/Seoul` 오늘 기준 과거 3개월부터 미래 3개월이다.
- 공개 서비스 origin은 deploy-project 규칙에 따른 `https://calendar.app.hurdoo.kr`이다.
- 관리자 비밀번호는 로컬 CLI가 만든 검증용 해시를 deployd managed secret으로 주입한다.
- 공개할 일정 날짜는 현재 보존 중인 전체 데이터 또는 선택한 시작일·종료일 중 고를 수 있다.
- 활성 공유 주소는 관리자 화면에서 다시 확인할 수 있고 새 주소는 `#share=` fragment 형식을 사용한다.
- 공유 주소 재구성에는 관리자 세션 키와 분리된 `SHARE_LINK_SECRET`을 사용한다.

## 12. 승인된 가정과 보안 기본값

- **A-001 단일 소유자:** MVP는 관리자 1명과 Google 계정 1개만 지원한다.
- **A-002 날짜 의미:** 일정 공개 범위 `ALL`은 현재 보존된 과거·미래 3개월 read model 전체를 사용한다. `SELECTED`는 고정된 시작일·종료일의 양 끝 날짜를 포함한다. 접근 종료시각은 배타적이다.
- **A-003 시간대:** 기본 정책 시간대는 `Asia/Seoul`이며 Google 원본 시간대와 종일 날짜는 별도로 보존한다.
- **A-004 캘린더 범위 모드:** `ALL`은 현재와 미래의 활성 캘린더 전체를 포함한다. 하나라도 제외하면 `SELECTED`로 전환되어 저장된 허용 목록만 사용한다.
- **A-005 방문자 보기:** 모바일 기본값은 목록, 820px 이상 화면의 기본값은 월간이다. 주간은 모든 화면에서 월–일×24시간 시간표이고 모바일은 가로 스크롤한다. 종일·시간 미정 일정은 상단 행에 둔다. 월간은 일정 이름을 표시하고 날짜 선택 시 해당 주간으로 전환하며, 사용자가 고른 보기 모드만 로컬에 기억한다.
- **A-006 실시간 목표:** Google 알림 도착 후 로컬 반영 p95 10초, 알림 누락 복구 최대 5분을 초기 측정 목표로 사용한다. Google 자체 알림 전송 시간은 서비스가 보장하지 않는다.
- **A-007 방문자 세션:** 링크의 원문 토큰은 검증 후 HttpOnly 방문자 세션으로 교환하고 깨끗한 URL로 이동한다. 같은 원본 링크는 만료·폐기 전까지 다시 사용할 수 있다.
- **A-008 상세 저장 최소화:** 방문자에게 보여주기로 승인된 이벤트 필드와 동기화에 필요한 식별·버전 메타데이터만 로컬에 저장한다. `private` 일정 상세 마스킹은 개인정보 보호 기본값이며 사용자가 명시적으로 변경하기 전까지 유지한다.

## 13. 결정이 필요한 사항

- 남은 제품 차단 결정은 없다. 구현 시작 여부는 사용자가 별도로 지시한다.
- Google 연동 smoke test 전 Google Cloud 프로젝트에서 Calendar API, OAuth 동의 화면, Web application client를 준비해야 한다. 실제 `GOOGLE_CLIENT_ID`와 `GOOGLE_CLIENT_SECRET` 값은 저장소나 채팅이 아니라 deployd 대시보드의 **Secrets**에서 사용자가 직접 등록한다.
- `SHARE_LINK_SECRET`도 `pnpm secret:generate`로 별도 생성해 로컬 `.env.local`과 deployd **Secrets**에 사용자가 직접 등록한다. 기존 키와 재사용하지 않는다.
- Google OAuth callback URI는 `https://calendar.app.hurdoo.kr/api/v1/admin/google/callback`으로 고정한다.
- 로컬 개발용 Google OAuth callback URI는 Vite 개발 서버가 Fastify로 proxy하는 `http://localhost:8464/api/v1/admin/google/callback`을 사용한다.
